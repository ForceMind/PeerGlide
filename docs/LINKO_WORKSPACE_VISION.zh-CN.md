# Linko（屏跃）长期愿景：统一远程工作空间

日期：2026-11-07。
状态：用户确认的远期产品方向；以下能力均为规划，不代表已经实现、经过真机验收或进入当前版本承诺。

延续 [UI 方案](LINKO_UI_DESIGN.zh-CN.md) 与 [窗口桥接研究](WINDOW_BRIDGE_RESEARCH.zh-CN.md)。不替代原有 ROADMAP、DEVELOPMENT_PLAN、LOCAL_CODEX_HANDOFF 与 VALIDATION，不重编号 M0–M5 / G1–G2 / WB0–WB5。

## 1. 用户目标与产品定位

在跨电脑键鼠协同、双向跨屏窗口显示的基础上，未来提供类似 UU 远程的远程访问体验：手机、平板也能控制电脑；多个独立设备的桌面或应用窗口，可放进同一个能够平移、缩放、排列的远程工作空间。

建议定位：**Linko 将分散在不同设备上的屏幕、应用窗口和输入能力，组织成一个统一的个人工作空间。**

这里的“远程接口”指经认证、经授权的显示与交互会话，不是直接向公网暴露一个无保护端口。应用和计算仍在来源设备运行，不承诺任意跨系统进程迁移。品牌仍为 Linko / 屏跃；本次不更改仓库、crate、安装标识或协议名称。

## 2. 三种体验使用共享能力，但不是同一功能

| 模式 | 用户体验 | 必须保留的区别 |
| --- | --- | --- |
| 桌边协同 | 一套键鼠在身边多台电脑间切换 | 每台电脑保留自己的本地桌面；不默认传输画面 |
| 远程访问 | 电脑、手机或平板查看并控制另一台电脑 | 视频、音频、输入、剪贴板、文件需要独立能力与授权；跨公网需要连接基础设施 |
| 统一工作空间 | 在一个可缩放画布里摆放来自多个设备的桌面/窗口 | 是多个独立会话的组合，不是所有设备共享同一个操作系统或桌面会话 |

“屏幕布局”配置真实/虚拟显示器之间的跨屏关系；“工作空间”组织远程画面的位置。两者必须使用独立模型：平移画布里的设备面板，不得意外修改来源系统显示器拓扑或跨屏边缘。

## 3. 分阶段范围：现在留接口，不提前建设整个平台

| 范围 | 建议顺序与交付边界 |
| --- | --- |
| 当前主线 | 完成原有 Windows/macOS KVM、真实双机验收、稳定连接与恢复、Linko UI；数据协作继续遵守原里程碑依赖 |
| 窗口与扩展屏 | 沿 WB 研究轨道分别验证虚拟扩展屏、单窗口捕获/代理；先显式选源并分享，再研究自然边缘拖窗 |
| 单会话远程访问 | 在已有画面与控制能力上，先稳定一对一远程桌面、断线恢复和独立授权；公网可作为单独实验支线，不依赖窗口代理全部完成 |
| 手机/平板控制端 | 先覆盖手机控制 Windows/macOS，增加触控、虚拟键盘、外接键鼠、横竖屏与后台恢复；不因控制端存在就声称手机可被控 |
| 多会话工作空间 | 先实现少量桌面面板的平铺与焦点切换，再逐步支持缩放画布、工作区保存和独立应用窗口 |

这是依赖顺序而非日期承诺。不能以未来需求为由替换现有 Rust/eframe/QUIC、跳过 C06、启动新全局钩子、直接升级 v5 协议、部署服务器或安装驱动。原 G1 本地增强与 M4 数据协作不因本愿景被删除或暗中降级。

## 4. 现在需要保留的模型边界

以下名称是概念草案，不是要求立即增加 crate、SDK 或对外协议。

- **Device**：可信设备身份与能力集，不绑定永久“主机/从机”。同一设备能否同时发送和接收画面，需运行时协商与资源评估。
- **Surface**：可显示的来源对象，区分物理屏幕、虚拟屏幕、应用窗口。具有来源设备、临时对象 ID/代次、逻辑尺寸、像素尺寸、DPI、旋转与能力；不直接跨网络暴露 OS 句柄。
- **Session**：来源、查看端、会话代次、有效授权、传输状态与恢复状态。同一设备的多个窗口可以共用连接，但授权、队列和生命周期仍需隔离。
- **View**：客户端画布中的可见面板；区分画布缩放与改变源分辨率。来源窗口不支持调整大小时，客户端只能显示缩放/留边，而非假装调整成功。
- **Input ownership**：将操作准确路由到获得授权、持有控制租约的目标；目标 token、会话代次和映射版本必须验证。
- **Media/transport adapters**：捕获、编码、传输、解码、渲染分离。复用已有身份与安全约束，但 QUIC 本身不自动提供视频系统、NAT 穿透、中继或浏览器支持。
- **Workspace**：只保存布局、设备引用和显示偏好，不保存可直接恢复控制的票据，不默认保存截图、窗口内容或敏感标题。

本期只在确有复用需求的边界保持解耦，避免设计大量未使用接口。具体 schema、版本协商、传输选择与迁移均由后续 ADR 和测试决定。

## 5. 无限画布的具体产品定义

“无限”指用户可平移、缩放、组织工作面板，不是申请一个无限分辨率的系统显示器，也不是承诺无限路视频并发。

建议体验：桌面端同一画布展示 Mac 的编辑器、Windows 的完整桌面，以及另一台电脑的监控窗口；点击任一面板即可明确选择控制目标。手机端优先单面板沉浸操作，概览中切换设备或窗口，不把桌面密集布局直接缩小到手机。

运行约束：

1. 画布坐标、面板可见内容坐标、来源窗口/显示器逻辑坐标、实际像素坐标分别建模；包含缩放、裁剪、黑边、旋转、Retina 与 Windows DPI。面板发生变化时拒绝旧映射输入。
2. 用户手动输入默认只进入当前选中并获得租约的一个目标。切换前释放本端持有的合成按键，保留本地紧急退出；不可将一个键盘事件默认广播给全部设备。
3. “同时查看/连接多台设备”与“把一次输入广播到多台设备”是两个需求。后者不属于默认远控，若将来需要，须独立选目标、逐端授权、显著群控提示和一键停止，并重新评估风险。
4. 聚焦面板优先画质与帧率；背景缩略图降频；屏外面板暂停或限频。分别限制会话数、解码器数、GPU 内存、总码率和音频源；达到上限时给出明确提示，不承诺任意设备数量。
5. 音频默认只播放当前选定来源；多路混音、麦克风转发另行授权，防止回声与误收音。画布操作与触摸远程桌面采用可区分模式。
6. 缩放画布不等于调整来源分辨率；移动面板不等于迁移进程、文件或账号。拖拽文件与拖拽远程面板也要有不同反馈。

## 6. 公网与移动端的边界

公网路线建议评估“局域网/直连优先 + NAT 穿透 + 经授权的加密中继回退”。直连失败不是权限失败，中继成功也不代表已获控制权。设计要覆盖信令认证、设备绑定、连接滥用与速率限制、流量配额、撤权、过期票据、网络切换和重连后重新获得控制租约。中继不得要求读取媒体明文；流量成本与用户提示需要独立产品评估。

手机作为控制端、显示端、被控端是三个角色，必须分别建立 Android/iOS/iPadOS 能力与系统权限矩阵。首个移动目标仅为手机/平板控制已授权电脑，不承诺 iPhone/Android 均能被任意远程操控。

浏览器客户端不属于本期；不假定它能直接运行现有原生 QUIC/输入实现，后续按需比较 WebRTC 或其他受支持适配层。

## 7. 安全和故障恢复必须延续现有工程

- 配对不等于获得所有权限。输入控制不包含屏幕采集，屏幕观看不包含文件、剪贴板、音频或远程命令执行。远程终端/脚本执行不在本愿景授权内。
- 单窗口画面分享不自动等于单窗口安全隔离。若平台无法可靠限制输入目标，不得把会话宣传为“只能控制这个应用”；应降级观看或明确实际桌面级控制范围并另行征得同意。
- 被控设备始终保留可见连接状态、本地接管和紧急断开。屏幕锁定、权限撤销、会话代次改变时按策略停止采集/注入，不能绕过 UAC、Secure Input 或系统隐私机制。
- 双向分享不得形成画面递归捕获或输入回环。记录每个 Surface 的原始来源，排除 Linko 自己的远程视图；无法可靠排除时限制组合或拒绝该共享模式。不能仅靠普通层级标记就宣称解决 OS 级递归捕获。
- 断网时冻结画面须明确标识“已断开/画面已过期”；释放本端拥有的合成输入，恢复来源窗口可见位置或按已验证策略清理虚拟显示器，不删除应用状态。重新连接不盲目重放点击/按键。
- 连接记录只保留必要诊断与状态；不默认记录用户按键、剪贴板、视频、窗口标题或屏幕内容，不自动上传验收材料。
