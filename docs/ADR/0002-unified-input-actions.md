# ADR-0002：统一输入仲裁、可选本机手势与跨设备语义动作

日期：2026-11-01。状态：规划决定，随文档PR评审；非实现完成声明。

关联：[产品演进计划](../PRODUCT_EVOLUTION.zh-CN.md)、G1 #11、G2 #12。保留ADR-0001及协议v3所有已定义安全语义。本ADR不切换UI框架、不引入脚本依赖、不修改现有线协议。

## 背景

现有platform负责捕获/注入，core负责接收端权威租约和已按下输入账本，transport负责认证通信，desktop负责会话，eframe GUI管理独立worker。CaptureGate当前抑制逻辑服务远程控制，不能直接认为已支持“无连接的本机手势”。新功能必须扩展共享输入生命周期，不能复制第二套全局hook。

## 决定一：只保留一个输入所有权裁决点

规划流程：

```text
原生事件 → 来源标记/权限检查 → 紧急释放及本地接管
        → 同步短路径仲裁 → 本机普通输入 / 手势候选 / 既有KVM转发
        → 有界队列 → 纯识别/规则匹配 → 类型化动作 → 平台执行或授权远端请求
```

紧急中止、权限撤销和接收端物理输入接管始终高于手势和热角。底层hook必须在返回前作出最小的放行/抑制决定；不能先异步识别再试图撤回已送入应用的右键。识别、UI、磁盘、网络与脚本均不在hook中执行。队列满或worker异常时取消候选并解除屏跃抑制，回收已拥有的合成按键；这不等于保证重放此前被抑制的全部用户操作。

G1先本机：连接/远控未启用也能运行worker；控制远端期间G1不拦截，保持原始KVM。G2再扩展远端路径。关闭G1/G2后对现有协议v3和输入行为的回归必须通过。

## 决定二：输入来源与账本分离

内部来源拟定义 `PhysicalLocal`、`RemoteInjected`、`ActionInjected`、`RecoveryInjected`。远端注入和动作注入不再参与手势识别/转发；避免循环。系统标记只是事件处理线索，不是对同机恶意进程的认证机制，不宣称防御已控制本机的攻击者。

物理按下、已向本地应用送达的按下、已向远端送达的按下、屏跃自身合成按下分别记账。按下/抬起必须在同一归属域闭合；手势不能复用远程lease账本来掩盖本地合成状态。线程停止、失焦、锁屏、权限丢失、队列满、断开都有清理路径。

## 决定三：手势状态机与普通右键兼容

状态：Idle → Pending → Tracking → Recognized/Rejected/Cancelled → Idle。

| 状态/事件 | 决策 |
|---|---|
| Idle且禁用/应用排除/权限不足 | 原样放行，不占用输入 |
| 符合触发条件的右键按下 | Pending，记录目标与屏幕坐标、配置版本，暂缓右键对的投递 |
| 未过距离阈值即松开 | 在仍有效的原目标/原语义下提交一次平衡的普通右键；目标失效则取消并提示 |
| 过阈值且符合手势规则 | Tracking，记录有界轨迹；暂停普通边缘切换/热角 |
| 松开且置信度/分差通过 | 目标和权限再校验，通过后提交一次动作 |
| 长手势未知/歧义/超时 | 不执行动作，不把整段轨迹回放为任意右键拖拽 |
| 紧急停止/权限撤销/接管/目标失效 | 取消；清理所属输入；不转发到新目标 |

普通右键“恢复”是受验证的点击兼容策略，不是对所有应用右键按下时序完全透明。需要右键长按/拖动的CAD、游戏等可配置排除或不同触发键；必须实测。候选期间副键组合、滚轮、第三键策略明确且有回归，不允许猜测性执行。释放后重新武装切屏，防止取消瞬间跳到另一台电脑。

识别保持方向和书写顺序；不能把向上和向下在旋转不变归一化后当成同一形状。先方向折线与有界模板比较，采用重采样/去抖、拒识阈值和第一/第二候选差距；任意字形扩展在基准数据支持后增加。所有阈值为可测配置，不需要AI服务。

## 决定四：一个语义动作目录

新增 `peerglide-gestures` 与 `peerglide-actions`。输入broker优先作为现有platform/core的边界演进，未出现明确独立职责前不机械拆出更多crate。GUI保留eframe；原生覆盖层由platform适配，不假设普通GUI窗口已解决不抢焦点/多屏层级。

建议模型（字段名是设计，不是已发布API）：

- `ActionSpec`：稳定ID、schema版本、参数类型、风险级别、能力需求、幂等分类。
- `Rule`：触发器、应用条件、目标策略、优先级、ActionSpec引用；全局/设备/应用排除先于普通匹配。
- `ActionContext`：目标设备、会话代次、lease代次、上下文token、配置版本、触发序号、失效条件。
- `ActionResult`：Accepted / Executed / Unsupported / Denied / Cancelled / Failed / UnknownOutcome。

规则优先级：安全禁用/排除 > 精确应用规则 > 应用组 > 全局；同级冲突配置时拒绝或显式优先级，不由文件顺序偶然决定。设备专属路径与跨系统意图分离。复制/粘贴与原始按键发送是不同动作；Windows与macOS并不全量互换Ctrl/Command。最大化、全屏、关闭标签页、关闭窗口、退出应用分别定义。

快捷键注入执行前要核验当前焦点；尽可能使用原生目标窗口API。无法保证目标正确时取消，不擅自强制激活其他应用。已提交到OS不代表应用已完成；结果必须如实说明。

## 决定五：远端上下文、授权与顺序

G2由物理输入来源端识别一次。手势开始冻结目标设备/会话/lease；目标端根据有效控制前缀与光标锚点产生短期、不透明且绑定身份的上下文token。窗口句柄/AX引用只保存在其所属OS进程内。远端应用规则在目标端解析，不使用来源电脑的前台应用判定；需要返回时只返回最少的规则/能力信息。

上下文请求不得阻塞hook；未及时获得有效token则取消远端动作。动作执行前目标端重新验证token、窗口/焦点代次、权限及lease。焦点变化、连接中断、设备切换和接管使旧上下文失效，不能跟随新焦点或回退到本机。

新请求拟携带 request_id、action_id/version、经验证参数、target_token、会话/lease代次、短有效期与控制顺序屏障。有效期由接收端本地单调时钟约束，不能依赖两台机器时钟相同。受控动作只接受当前授权会话；未来非控制态后台动作需另立ADR。

控制消息必须保持与相关离散输入的因果关系：在同一可靠流有序，或显式等待输入序号屏障。保留v3正常返回的可靠Release；datagram不能提前撤销lease。动作必须在可执行上下文内提交或取消，不能利用延迟的响应在归还控制后继续输入。

去重缓存有界并绑定会话。短期重发相同request_id可查询已知状态；连接/进程故障后对非幂等动作不自动重放，返回UnknownOutcome而非谎称恰好一次执行。权限检查发生在接收端，输入授权不隐含文件/剪贴板/动作/脚本授权。

线协议新增能力先协商；旧端可继续只用兼容KVM，不能理解的动作明确禁用。改变现有行为或格式必须更新协议版本/ALPN及双端兼容测试。本文不将当前 `peerglide/3` 修改为另一版本。

## 决定六：配置和脚本边界

配置含schema_version、动作/规则稳定ID、功能开关。升级先校验、预览、备份、原子替换；失败恢复旧配置。同步规则不同步私钥、信任记录、系统权限、可执行路径或自动启动授权；跨OS不支持项显式禁用。

G1无Lua；G2首批无远程任意命令。后续Lua研究使用受限宿主接口、时限/内存/指令/并发预算及独立worker隔离，评审原生宿主函数的权限闭包。禁用io/os并不自动令宿主调用安全；不能把脚本权限伪装为普通鼠标控制。

## 反例和必须保留的测试

正常右键/右键拖拽冲突；手势过程中跨边缘；按住修饰键接管；动作产生的键再被捕获；单机无身份/无网络；目标窗口关闭；来源焦点与目标焦点不同；旧会话请求；失去响应；重复关闭窗口；大文件占满队列；GUI崩溃；捕获线程未退出就重连；权限撤销；版本不匹配。每类都应验证取消/恢复，不仅测试成功路径。

## 被拒绝方案

不嵌入MouseInc/Aitiy闭源核心；不复制不兼容许可代码；不新建第二产品/第二hook；不先做任意远程脚本；不为了原生UI宣传重写eframe；不让网络连接成为本机手势的必要条件；不把普通文件发送包装为原生跨屏拖拽。
