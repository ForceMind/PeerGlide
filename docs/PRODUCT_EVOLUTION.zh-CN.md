# 屏跃：阶段化产品路线与持续开发计划

版本：规划基线 1.0；日期：2026-11-01。

代码审查基点：`56174387563ba6a087c7db35c9c5e1e1031e593c`。本文件中的新增功能全部是计划，不代表代码实现或实机验收。生效范围：对原 M0–M5 的增量细化；原产品定位、工程约束、安全约束和未关闭验收继续有效。本文进入 main 前以其所在文档 PR 为评审基线，不能把计划当成已合并实现。

## 1. 产品方向与不变项

PeerGlide / 屏跃：多台电脑，一种体验。

主线仍是 Windows/macOS 优先的 Rust 多设备协同：独立电脑通过可信局域网连接共享输入，再扩展剪贴板和文件。新增鼠标增强作为同一产品内可关闭模块，让单台电脑也有价值；不另建产品、仓库、账号体系或第二套全局输入服务。

保留 Rust、现有 eframe GUI、QUIC/TLS、对等控制目标、MIT自主实现、本地优先。蓝牙/USB外设仍连接原电脑，不研究蓝牙配对迁移。Linux仍在既有范围内，但 Win/Mac 首发不能误称 Linux 输入已支持。无强制云端、账号或外部中转；本轮不部署服务、不操作用户电脑、不改变仓库公开状态、不购买证书。

产品差异化是可靠、可审计、跨系统的连续交互，而不是功能数或“首次发明”。MouseInc/Aitiy 的证据与取舍见 [研究文档](RESEARCH_MOUSEINC_AITIY.zh-CN.md)。

## 4. 产品需求边界

### 4.1 核心KVM

双机对等输入；键盘跟随当前控制目标；紧急释放和接收端物理输入接管优先。保留主屏M1范围，完整多显示器由M3-T独立增加显示器ID、负坐标、缩放、热插拔与旋转测试。Win快捷键与Mac快捷键不得全局机械互换，物理HID转发和语义动作是不同模式。IME组合、Unicode文本发送必须分别说明，不以键码覆盖声称完整输入法支持。

### 4.2 G1：本机鼠标增强的最小闭环

默认关闭，新用户主动启用。首批提供8种易区分轨迹和可编辑绑定；动作候选包括复制、粘贴、前进/后退、关闭标签页、最小化/关闭窗口、显示屏跃。危险动作不作为无提示默认。必须分别定义关闭标签页、关闭窗口与退出应用；Mac全屏也不等于Windows最大化。

最小界面为“启用→录制轨迹→选择动作→测试→保存”；应用规则和排除列表展开为高级设置。测试模式只显示匹配，不执行破坏性动作。绑定冲突有说明，暂停按钮始终可达；轨迹层不抢焦点。

本机模式可不创建身份、不配对、不打开网络监听。远程控制期间G1暂不截获手势，仍按现有KVM传送输入；跨机识别必须等G2，不偷偷以源电脑应用规则操作远端。热角、边缘滚轮和组合滚轮稍后加入，不能与切屏竞争。

### 4.3 M4：数据协同分三个交付切片

M4-A：Unicode文本剪贴板，按设备/方向授权；默认不上云、不保留历史；回环抑制、来源ID、内容大小和过期策略。敏感内容无法保证自动完全识别，提供手动暂停、应用排除及显式发送模式，不承诺“所有密码自动过滤”。

M4-B：图片剪贴板和显式文件发送。用户选择文件与目标，接收端确认和保存位置；分块、校验、续传、取消、磁盘不足及重名策略。下载临时文件完整校验后原子提交；防路径穿越、符号链接逃逸和自动执行。原生目录发送/符号链接默认不在第一切片。

M4-C：原生跨OS拖拽另做技术验证、设计和验收。把文件拖到屏跃发送区，或普通文件发送成功，都不能记为“跨屏拖进Finder/Explorer成功”。延后此切片不关闭 #6。

### 4.4 G2：跨设备动作

同一手势表达“复制”或“关闭窗口”，目标系统执行自己的语义适配；动作的目标设备、会话代次和窗口上下文在开始时确定，不能结束时改投另一设备。目标端解析应用规则；过期、离线、切焦点、被本地接管时取消，不回退为本机执行。

远程动作必须独立授权；键鼠控制、剪贴板、文件和脚本不是一个权限开关。共享底层传输，不共享无限权限。首批只做类型化白名单动作；截图传至另一台电脑需同时具备截图/图片传输授权与实现，不能随G2基础动作一起宣称完成。

### 4.5 后置能力

截图、贴图、离线OCR优先验证系统原生API与可选模型，模型独立下载、许可和资源计量；不随主程序强塞大模型。在线翻译/搜索传送文本需明确目的地与用户动作。Lua和可视化工作流在稳定动作API后研究；只禁用几个Lua库不能宣称完整沙箱。AI既不是手势识别必需，也不成为核心的网络依赖。

## 6. 接下来三个开发批次

第一批只解决可追踪的基线缺口：C01单独PR，然后C02、C03、C04、C05分别提交；不混入手势、OCR或UI换框架。每个PR附错误复现、测试与回滚边界。C01优先检查测试目录隔离，不直接把未验证假设写成根因。

第二批补C06验收包、P01与M2/M3日常可用闭环。可并行做G01/G02纯逻辑设计/测试，但未通过C06前不能把新增输入拦截当作可发布功能。没有获授权实机时，记录blocked并继续不依赖实机的工作，不能重复宣称“已全部做好”。

第三批推进G03/G04及D01，分别验收单机增强和文本协同，再进入D02/D03与G2。不要为了实现G2任意远程脚本而跳过配对/权限/目标上下文设计。

分支按现有增量PR模式；本轮不创建长期第二主线。并行开发采用文件/接口责任边界，同一协议定义只由一个PR修改。合并前核对最新main，不强推覆盖其他工作。

## 7. 验收矩阵与工程预算

下列数字是拟定验收目标，不是实测成绩。建立基线后只能经记录评审调整，不因达不到而静默降低。

### A. 输入与恢复（C06）

Windows/Mac双向分别覆盖Bluetooth/USB、四边进入/返回、Windows100/150/200%与Mac Retina、普通/全屏窗口、权限拒绝和撤销、Secure Input/UAC边界、中文/英文输入法、连续/高分辨率滚轮。支持矩阵要写实际OS/build和硬件，不能把macos-latest或Aitiy最低版本当成屏跃最低版本。

每个关键故障场景至少100轮：按住修饰键/鼠标时断网、worker退出、接收端接管、紧急停止、睡眠恢复。记录是否恢复、耗时、残留状态；不得用会记录真实键内容的常驻调试实现。每个方向500次切换与8小时基础会话作为预览目标；正式候选24小时耐久。安全拒绝不是功能失败，但必须可理解且不锁住用户输入。

### B. G1识别与不干扰

至少8种默认轨迹×5名测试者×20次=800条标注正样本，至少2000条普通右键/抖动/滚动/拖动等负样本。正样本识别率目标≥95%，负样本误触发≤0.5%；对危险动作另要求验证集0误执行。录制样本经同意且不含屏幕/按键内容。左右上下及相反方向必须可区分；拒识优于猜错。

125/500/1000Hz鼠标与至少3档DPI下测试。短右键必须成对且恰好一次，取消/失焦/崩溃不得留下虚拟按下状态。CAD、游戏等原生右键拖动冲突应用默认建议排除，触控板副键单独验收，不宣称与实体鼠标完全一致。

### C. 热路径与资源

拟定hook回调p99<1ms、G1识别计算p95<5ms（固定64点/最多100模板），禁止在hook等待网络、磁盘、UI、OCR或脚本。释放到本地动作提交p95<50ms，必须注明不等于目标应用完成时间。测量在固定参考设备进行，报告采样数、构建、后台负载与分位数。

KVM测量使用同一时钟的发送→接收确认往返指标，显示端到端另测，不能跨机直接相减未同步时间戳。文件满负载时输入确认p95相对空闲增加目标≤10ms；有线/Wi-Fi分开记录。进程常驻内存/CPU先建立纯KVM基线，G1 idle增量目标≤20MiB、≤单核0.5%，GUI和OCR另记账。

### D. 资源限制初值

文本剪贴板默认1MiB UTF-8；图片编码≤16MiB、解码≤64MiB且≤1600万像素，任一超限均拒绝；这些是待测初值，配置和协议均有上界。文件初始分块1MiB、每文件最多4在途块、最多2个活跃发送；全局队列仍需独立字节预算，不能只限制条目数。用户自选文件大小策略与磁盘配额，接收端始终可拒绝。

### E. 安全与发布

恶意发现、身份替换、配对重放、旧租约、重复动作、过大消息、畸形图片、路径穿越、权限撤销、对端崩溃均有自动测试；焦点/权限/输入法及原生拖拽需实机。S02依赖真实授权的签名凭据；缺少凭据不得标记签名完成。实验性未签名包必须明确标注，不能要求禁用系统防护。

## 8. 核心风险与降级

| 风险 | 缓解 | 可接受降级 |
|---|---|---|
| 手势吞掉普通右键 | Pending账本、短点击恢复、排除/替代触发键、真实应用回归 | 关闭该应用/设备的手势，不影响KVM |
| 手势与屏幕边缘冲突 | 紧急/接管优先，手势进行中锁定切换，边界重新武装 | 热角/边缘滚轮延后 |
| 远端应用上下文错误 | 接收端令牌、代次与焦点再验证 | 取消并提示，不改投本机或新窗口 |
| 协议演进破坏v3 | 能力协商、显式版本、前缀顺序屏障 | 旧端仅KVM，新动作不可用 |
| 文件传输挤占输入 | 独立流、字节预算、公平调度、输入优先 | 限速/暂停大文件 |
| 实机和签名资源不足 | 分开工程完成与验收，保留blocked证据 | 不发布正式支持承诺 |
| 范围膨胀 | G1/G2开关、模块预算、每阶段冻结范围 | OCR/Lua/工作流不阻塞核心交付 |
| 许可不明 | 自主实现，逐依赖记录许可，竞品仅研究 | 不复制素材/代码/脚本包 |
